# 마이그레이션 규약 (Stage 1부터 적용)

`supabase/` 최상위의 기존 `.sql` 파일들(profiles.sql, problembank.sql, vocab.sql 등)은
"여러 번 실행해도 안전한(idempotent)" 스냅샷 방식이었다. 이 방식은 실행 순서와
되돌리기(rollback)가 불명확해지는 단점이 있다.

**영어 서브시스템(단어 완전학습)부터는 타임스탬프 마이그레이션 방식을 쓴다.**

## 파일명 규칙

```
supabase/migrations/YYYYMMDDHHMM_짧은_설명.sql
```

예: `202608140900_create_vocab_v2_schema.sql`

## 규칙

- 한 파일 = 한 논리적 변경 단위 (테이블 생성, 컬럼 추가, 정책 변경 등을 묶어도 되지만 너무 크게 만들지 않는다)
- 파일은 **원칙적으로 수정하지 않는다** — 잘못됐으면 되돌리는 새 마이그레이션을 추가한다
- 파일 상단에 목적과 "되돌리는 법" 주석을 남긴다
- 실행은 지금과 동일하게 Supabase SQL Editor에 순서대로 붙여넣어 실행한다 (CLI 마이그레이션 자동화는 이후 단계에서 검토)

## 기존 파일과의 관계

기존 `supabase/*.sql`(수학 문제은행, 강좌, 권한 등)은 그대로 둔다. 손대지 않는다.
새 영어 서브시스템 스키마만 이 규칙을 따른다.
